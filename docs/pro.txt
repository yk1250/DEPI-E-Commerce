# منصة حجز الكشوفات الطبية (Clinic Platform)
مشروع تخرج - تدريب ITI / DEPI - فريق من 5 أفراد

---

## 1. نظرة عامة

منصة لحجز الكشوفات الطبية أونلاين. المريض يبحث عن دكتور (بالتخصص أو التقييم أو السعر)، ويحجز ويدفع، والدكتور يدير أجندته ويشوف التاريخ المرضي للمريض. الإدارة تتابع العيادات والأطباء والتقارير المالية.

**القاعدة الأساسية:** أي مستخدم ما يقدرش يوصل لبيانات مريض تاني.

### الأدوار (RBAC)
| الدور | الصلاحيات |
|---|---|
| Admin | إدارة العيادات والتخصصات والأطباء المعتمدين، التقارير المالية، الكوبونات |
| Doctor | الأجندة، أوقات العمل والإجازات والأسعار، عرض التاريخ المرضي للمريض، الرد على الرسائل |
| Patient | البحث والحجز والدفع، التاريخ المرضي والمرفقات، تقييم الدكتور، مراسلة الدكتور بعد الكشف |
| Receptionist | متابعة المواعيد، تأكيد الدفع في العيادة، تسجيل وصول المريض |

---

## 2. التقنيات

| الجزء | التقنية |
|---|---|
| Backend | ASP.NET Core Web API (.NET 10)، Clean Architecture |
| Database | SQL Server + Entity Framework Core |
| Auth | ASP.NET Core Identity + JWT + OTP (مخصص) |
| Realtime | SignalR (حالة الحجز، الرسائل) |
| الدفع | Paymob Sandbox + الدفع في العيادة |
| Jobs | Hosted Service أو Hangfire (التذكيرات، انتهاء الحجز المؤقت) |
| Caching | Memory Cache أو Redis (التخصصات والأطباء الأكثر طلباً) |
| Logging | Serilog |
| التوثيق | Scalar (`/scalar`) + Postman Collection |
| Localization | Resource Files، عربي / إنجليزي مع RTL |
| Frontend | **لسه ما اتحددش** (انظر قسم القرارات المفتوحة) |

---

## 3. هيكل المشروع

```
medical booking.slnx
├── Clinic.Domain          Entities، Enums، Exceptions (من غير أي packages)
├── Clinic.Application     Use Cases، DTOs، Validators، Interfaces
├── Clinic.Infrastructure  DbContext، Configurations، Identity، Paymob، Files، Jobs
└── Clinic.API             Controllers، SignalR Hubs، Middleware، Program.cs
```

**قاعدة الاعتماديات:** الطبقة الخارجية تعرف الداخلية، والعكس لا.
- `Domain` ما يعرفش أي حاجة.
- `Application` يعتمد على `Domain` بس.
- `Infrastructure` يعتمد على `Application` و`Domain`.
- `API` يعتمد على `Application` و`Infrastructure`.

## 6. القرارات المفتوحة

لازم تتقفل **قبل** ما نقسم الشغل، لأنها بتأثر على الـ Entities والـ Modules:

1. **قائمة الانتظار:** إزاي الربط بالميعاد المفتوح؟ وإزاي الإشعار بيتبعت؟

3. **OTP:** هيتبعت بإيميل ولا SMS؟ وأنهي خدمة؟
4. **Frontend:** MVC ولا React ولا Angular؟
5. **مين المسؤول عن الدمج النهائي؟** (شخص واحد بس بيلمس الملفات المشتركة)

القرارات المسجلة بالفعل في `docs/decisions.md`:
- السعر يتحفظ على `Appointment.PriceSnapshot` وقت الحجز.
- الشات يفضل مفتوح 14 يوم بعد الكشف المكتمل.

### تفاصيل كل مسؤولية

- رفع المرفقات: التحقق من النوع والحجم، وحفظ بمسار آمن.
- **قاعدة الأمان:** المريض يشوف بياناته بس، والدكتور يشوف المرضى اللي عنده مواعيد معاهم بس. تتكتب في الـ Application layer، وكل endpoint لازم يتراجع.

## 8. Git وقواعد الشغل

### الفروع
```
main            النسخة المستقرة، محدش يكتب عليه مباشرة
develop         التكامل، كل الدمج يحصل هنا
feature/auth        الشخص 1
feature/doctors     الشخص 2
feature/booking     الشخص 3
feature/payments    الشخص 4
feature/medical     الشخص 5
```

### الإعداد الأول (مرة واحدة، شخص واحد)
1. اعمل ريبو فاضي على GitHub.
2. ارفع المشروع الحالي على `main`، واعمل `develop` منه، وارفعه.
3. أضف كل الأفراد كـ **Collaborators** على الريبو.
4. فعّل **Branch protection** على `main` و`develop`: ممنوع push مباشر، ولازم PR بمراجعة واحدة على الأقل.

### دورة الشغل لكل فرد
```
1. git checkout develop && git pull
2. git checkout -b feature/<المسؤولية>
3. اشتغل في الفولدرات بتاعتك بس
4. git add . && git commit -m "feat(<المسؤولية>): ..."
5. git push -u origin feature/<المسؤولية>
6. افتح Pull Request إلى develop
7. شخص تاني يراجع، والمسؤول عن الدمج يعمل merge
8. كل فرد يرجع يعمل pull لـ develop قبل ما يكمل
```

### تسمية الـ Commits
- `feat(auth): add JWT login`
- `fix(booking): handle concurrent slot lock`
- `chore(infra): update packages`
- `docs: update todo`

## 9. قواعد عشان ما يحصلش تعارض

### ممنوع تعدّل (إلا المسؤول عن الدمج)
- `Clinic.Domain/Entities/*` و`Clinic.Domain/Enums/*`: الـ Entities مقفولة، أي تعديل يتعمل بعد اتفاق الفريق كله.
- `Program.cs`
- `DependencyInjection.cs`
- `AppDbContext.cs`
- `Clinic.*.csproj`: إضافة package تتعمل بالاتفاق.

### بدل التعديل على الملفات المشتركة
كل مسؤولية تعمل **Module** خاص بيها، زي `BookingModule.cs` فيه `AddBooking(this IServiceCollection)`. والمسؤول عن الدمج بيضيف سطر واحد لكل module في `DependencyInjection.cs`.

### الـ Migrations
- **ممنوع تعمل Migration على فرعك.**
- الـ Migration بتتعمل مرة واحدة بعد الدمج الكامل، من المسؤول عن الدمج، وتتطبق على داتابيز التكامل.
- أي تعديل على الـ Entities قبل الـ Migration يتعمل في الفرع اللي بيحتاجه، ويتدمج الأول.

### لو محتاج بيانات من مسؤولية تانية
1. اكتب **interface** في فولدرك.
2. اعمل **stub** عشان تشتغل محلياً.
3. لما الدمج يحصل، المسؤول عن الدمج يبدل الـ stub بالتنفيذ الحقيقي.
